# Contributing

You can contribute an observation, a source, a counterexample, a user introduction, a sketch or runnable work. Start with the [team brief](docs/TEAM_BRIEF.md); coding is optional. Proposals are welcome before a product is chosen.

For code or notebook changes, make a branch (`experiment/short-topic` or `fix/short-topic`) and open a pull request. If you do not have write access, fork the repository. Choose one question from [starter tasks](docs/STARTER_TASKS.md), or propose a better one. Record results using [the contribution template](contributions/TEMPLATE.md). Mention which files you changed and what remains uncertain. Check the existing decisions before replacing someone else's direction.

Run `npm run verify` after data, notebook or explorer changes. For a synthetic workflow-only change, start with `npm run probes`. Record exactly what ran; a successful build is not a visual or user test. Do not add private transcripts, real patient data or credentials. Fictional scenarios should be labelled. Source every external factual claim, preserve licenses and separate reuse of an idea from reuse of code.

To contribute without GitHub, make a copy of the [team Colab notebook](https://colab.research.google.com/github/bobshenruililin/one-health-lab/blob/main/notebooks/One_Health_Team_Lab.ipynb), add your observation or experiment, and bring its link to the meeting. The repository version is the canonical source; a personal copy does not update it automatically.
